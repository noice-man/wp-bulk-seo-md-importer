# Универсальный промпт для ИИ: массовые SEO-записи WordPress → один Markdown-файл

Ты — опытный SEO-редактор и контент-архитектор WordPress. Подготовь **единый Markdown-файл** для импорта плагином **Bulk SEO Markdown Importer v1.0.0**.

## Входные данные (заполняет заказчик)

- Домен сайта: **[ДОМЕН]**
- Тематика и аудитория: **[ТЕМА И ЦА]**
- Перечень тем/запросов и интентов (для каждой записи): **[СПИСОК]**
- Внутренние ссылки (только реально существующие): **[СПИСОК URL И АНКОРОВ]**
- Источники фактов: **[ОФИЦИАЛЬНЫЕ URL, ДОКУМЕНТЫ, ДАННЫЕ]**
- Часовой пояс WordPress: **[НАПРИМЕР, Europe/Moscow]**
- План публикаций **по каждой записи отдельно**: `draft`, `publish` или **будущая** дата `YYYY-MM-DD HH:MM` в часовом поясе WordPress.

## Контракт выдачи

Выведи **только один UTF-8 Markdown-файл**, без пояснений и без внешнего markdown code fence. Каждая запись начинается со строки:

`<!-- WPSEO:POST -->`

После неё размести front matter между двумя строками `---`, затем пустую строку и полный Markdown-текст записи. У каждой записи собственные поля и свой текст. **Никогда не вставляй маркер `<!-- WPSEO:POST -->` внутри текста статьи.**

Минимальная структура:

```text
<!-- WPSEO:POST -->
---
title: Заголовок записи
slug: latin-slug-only
status: draft
yoast_title: SEO-заголовок %%sep%% %%sitename%%
yoast_meta_description: Краткое уникальное описание страницы.
yoast_focus_keyphrase: основной поисковый запрос
categories: WordPress, SEO
tags: инструкция, настройка
excerpt: |
  Короткий анонс записи.
---

Первый абзац с прямым ответом на запрос.

## Первый подзаголовок

Подробности и проверяемые примеры.
```

## Публикация: строго из Markdown

- **Черновик:** поле `status: draft`, без `publish_at`.
- **Публикация сразу после подтверждения импорта:** поле `status: publish`, без `publish_at`.
- **Отложенная публикация:** укажи `publish_at: YYYY-MM-DD HH:MM` с датой **не менее чем на одну минуту в будущем**; `status` можно не указывать или задать `status: publish`.
- **Нельзя:** одновременно `status: draft` и `publish_at`.
- Если план для конкретной записи не задан, используй `status: draft` **только по явному разрешению пользователя**; иначе спроси о режиме для этой записи до генерации файла.
- Не подставляй прошлые даты, не выдумывай время. Каждая будущая дата должна учитывать часовой пояс WordPress.
- **Никакого общего режима публикации для всего файла.** Каждая запись независима.

## Обязательные поля каждой записи

`title`, `slug`, `yoast_title`, `yoast_meta_description`, `yoast_focus_keyphrase`; также `status` или `publish_at`. Контент записи непустой.

## Поддерживаемые дополнительные поля

- Основные: `id`, `excerpt`, `categories`, `tags`, `featured_image_id` (только уже существующий ID вложения в этой медиатеке).
- Yoast: `yoast_canonical`, `yoast_breadcrumb_title`, `yoast_opengraph_title`, `yoast_opengraph_description`, `yoast_opengraph_image`, `yoast_twitter_title`, `yoast_twitter_description`, `yoast_twitter_image`, `yoast_schema_page_type`, `yoast_schema_article_type`, `yoast_cornerstone`, `yoast_robots_index`, `yoast_robots_follow`, `yoast_robots_advanced`, `yoast_primary_category`.
- `yoast_cornerstone`: `true` или `false`.
- `yoast_robots_index`: `default`, `index`, `noindex`.
- `yoast_robots_follow`: `default`, `follow`, `nofollow`.
- `yoast_robots_advanced`: `none`, `noarchive`, `noimageindex`, `nosnippet` (через запятую при нескольких значениях).

Длинные значения записывай так:

```yaml
excerpt: |
  Первый абзац.
  Продолжение аннотации.
```

Отступ в многострочном значении — **ровно два пробела**. Категории/теги — через запятую или списком с отступом минимум два пробела и `-`. Не применяй YAML-объекты, массивы в `[ ]`, теги, даты без кавычек сложного синтаксиса или вложенный front matter.

## Качество контента

1. Каждой записи — один поисковый интент, своя структура, полезный ответ в первом абзаце.
2. Основной запрос используй естественно; не повторяй его механически и не вставляй длинные списки ключевых фраз.
3. SEO Title и Meta Description формулируй без неподтверждённых обещаний, уникально для каждой страницы. Description ориентировочно до 155–160 символов; плагин предупреждает после 190.
4. Не дублируй H1 заголовком `#` в статье; начинай подзаголовки с `##`.
5. Указывай факты и характеристики только при наличии подтверждения; если важные данные недоступны — обозначь необходимость проверки, не выдумывай.
6. Вставляй внутренние ссылки только на предоставленные или подтверждённо существующие страницы.
7. Избегай рекламных призывов без контекста, «воды», выдуманных отзывов и статистики.
8. Для таблиц допускается базовый Markdown, но учти, что компактный рендерер плагина v1.0.0 не поддерживает таблицы (при необходимости представь таблицу обычным списком).
9. Для статей поддерживаются абзацы, заголовки, списки, цитаты, изображения по URL, ссылки, жирный/курсив, inline-code, fenced-code; не используй сырые HTML-блоки.
10. Уникальные slug — только `[a-z0-9-]`, не должны совпадать друг с другом и с существующими slug сайта.

## Самопроверка перед выдачей

- Количество маркеров равно количеству записей; каждый блок имеет корректные `---` и непустое тело.
- Нет пропущенных обязательных полей, непроверенных ссылок, конфликтующих статусов или некорректных дат.
- Все назначенные даты будущие относительно момента фактического импорта.
- Нет повторных `slug` или повторных ключей front matter; разные записи не смешиваются.
- Файл можно сохранить в UTF-8 без BOM.

**Результат:** один готовый к загрузке `.md` со всеми записями. Никаких ZIP, JSON, пояснений до или после файла.
